## 7. 建议的下一批改进（按优先级）

1. **`NOT_FOUND` 的下一步提示改为路径动作**
   - 对单个文件/批量读取：提示“用 `fs_list` 检查父目录，确认文件名/工作区”。
   - 批量读取保留每个成功项的同时，在顶层摘要明确“M 个成功、N 个路径不存在”，避免模型把整批当作全失败重来。
2. **搜索范围提示**
   - 当 `path="."` 或宽目录搜索达到较大扫描量时，在 outcome/nextAction 中提示先用 `fs_list` 缩小到具体子目录；不要仅靠 1 GiB 预算完成根扫描。
   - 不新增索引系统；先观察窄路径使用率。
3. **`MISSING_EDIT` 的可操作性**
   - 返回必须重新读取的具体文件/窗口；若可行，给出导致失败的第一个 edit 索引（不返回完整正文）。
   - 保持 dry-run 和 stale guard，不自动猜测替换位置。
4. **失败后恢复路径的观测**
   - 用本次 V2 读取摘要区分正常续读、同一窗口重复、跨文件探索；需要完整参数的任务再关联 `inputSummary` 与结果。
   - 继续记录 `resultTruncated`，但不要把截断自动当作错误。
5. **暂缓**
   - 写入返回统一 sha256：本样本中 `fs_write` 结果只有 bytes/path，B 确有用 shell 查 hash 的往返；但样本不足以证明收益，继续观察“写入→查 hash→patch”的频率。
   - 搜索索引/组合执行工具：当前主要成本是范围选择和路径探索，先不引入新系统。
