# ADR-0022：V2 文件契约与可选本地 Agent 委派试点

- 日期：2026-10-26
- 状态：Proposed for pilot implementation（尚未作为生产能力发布）
- 基线：V2 / `9defb33fd24774e4cfd28389b9bb7918f77ca945`
- 方案：[V2_AGENT_WORKFLOW_PILOT](../architecture/V2_AGENT_WORKFLOW_PILOT.md)

## 背景

远端已经能通过 MCP 批量读写、打补丁、搜索和审计 Git 工作区。主要缺口是读写版本衔接、有限输出的完整性表达，以及多步骤执行后可恢复、可审查的状态。dsh-ops 提供了文件与结果契约的参考；codex-with-chatgpt 展示了远端规划/审查和本地执行的分工。P05 已有授权与 V3 Run 设计，应在现有边界内做小规模验证。

## 决策

1. 先兼容扩展现有文件工具，以 `contract_version: 2` 引入范围读取、同原文多编辑、结果状态和响应预算。旧调用保持兼容。
2. 再加入默认禁用的 AgentTaskService。控制消息只携带任务和引用，文件与日志通过授权后的 MCP 查询获取。
3. TaskRepository 与 AgentProvider 是独立接口；生命周期和证据属于 P05。首个真实 Provider 为本机 Codex CLI，先用 fake provider 验证。
4. 每 slot 单任务，SQLite 持久化调度意图和状态。未知状态不自动重放；审批绑定具体调度，不因任务异步化而扩大授权。
5. 使用独立 Git clone 作为任务工作副本，绑定已提交且干净的基线；副本只承诺隔离工作内容与 Git 元数据。真实进程仍需明确的本地可信主机模式、sandbox 及进程树终止验证。
6. 执行、验证和审查分开记录，审查绑定 evidenceDigest；首版不自动合并或推送。
7. 与 ADR-0012、0015、0018 的方向保持一致；这里是 V2 的有限试点，不宣称完整实现 V3，也不搬运整条 V3 分支。

## 备选方案与取舍

| 方案 | 优点 | 未选择的原因 |
| --- | --- | --- |
| 继续只增加细粒度工具 | 改动小、既有授权直接适用 | 无法解决长任务恢复与执行证据生命周期；保留为阶段 A |
| 直接复制 C2C 浏览器循环 | 接近远端对话体验 | UI 时序与会话检查点不等于持久化调度；引入额外运行依赖 |
| 立即迁入完整 V3 内核 | 长期结构统一 | 当前 V2 无实现，变更面过大，难以单独确认收益 |
| linked worktree 执行 | 快、节省空间 | 共享 common Git metadata；首版选择独立副本减少源仓库耦合 |
| 由 Provider 自己保存状态与测试声明 | 接口少 | 切换 Provider 后状态不可统一，测试自述缺少监督证据 |

## 代价与退出条件

- SQLite 在当前 Node 版本仍是 experimental，必须通过重启、并发、磁盘错误验证，并隔离在适配层。
- clone 增加磁盘与准备时间；试点保留配额并明确清理，先测量再优化。
- CLI workspace sandbox 不等于 P05 每工具权限。此模式不适用于要求强整机读取隔离的工作负载。
- 进程树终止、授权对账或证据访问控制任一门槛未通过，真实 Provider 保持禁用；阶段 A 仍可独立交付。
- 实测若委派不优于直接工具的成功率/成本，则保留接口与试验记录，不默认推广。

## 验证与迁移

按两个实施计划逐项验收。未来 V3 接管时，通过 TaskRepository 导出版本化上下文、事件和证据索引，再由迁移器导入；不能让两个 scheduler 同时拥有一个 slot。Provider 接口继续复用，V2 任务历史保持只读可查。
